# DATLUME 基本設計書

最終更新: 2026-10-05

## 1. 全体アーキテクチャ
DATLUME は「収集」「正規化・監査」「公開データ生成」「静的ビルド」「動的詳細ページ」「Cloudflare配信」を分離した構成を採る。

```text
公式データ/API/Web
    ↓ Python collectors
Raw / SQLite / normalized data (Ubuntu)
    ↓ build scripts
public/data + src/data
    ↓ Astro build
静的HTML / JSON / JS / CSS (dist)
    ↓ Cloudflare Pages
通常ページは静的配信
    └─ Pages Functions: 上場企業詳細 / 公共調達企業詳細
```

## 2. 技術スタック
- フロント: Astro 7
- グラフ: ECharts 6
- 地図: MapLibre GL JS 6.11.1
- E2E: Playwright
- 収集/正規化: Python 3
- 公共調達保存: SQLite
- 配信: Cloudflare Pages / Pages Functions
- 実行環境: Ubuntu + Node.js 22系

## 3. 配信方式
### 静的ページ
トップ、各領域トップ、ランキング、都道府県、業種、年度、発注機関等はAstroで静的生成する。
静的ページはFunctionsを経由せずCloudflare Pagesのアセットとして配信する。

### 動的ページ
`public/_routes.json` により次だけFunctions対象とする。
- `/listed-companies/{securityCode}/`
- `/procurement/companies/{companyId}/`
一覧・比較・業種ページは明示的にFunctions対象から除外する。

## 4. URL設計
- `/` — 総合入口
- `/procurement/` — 公共調達
- `/realestate/` — 不動産・暮らし
- `/regional/` — 都道府県別推移
- `/employment-economy/` — 雇用・賃金
- `/business-industry/` — 企業・産業
- `/agriculture/` — 農業・食の産地（市町村別品目・推計産出額）
- `/listed-companies/` — 上場企業
- `/unlisted-companies/` — 未上場企業
- `/economy-prices/` — 経済・物価
- `/energy/` — エネルギー
- `/topics/` — 話題のトピック（日本語版Wikipedia閲覧動向）
- `/about-data/` — データ出典・定義
- `/privacy/` — プライバシー・広告・Cookie
- `/analytics/` — サイト統計

## 5. データ配置
- `data/raw/` — 原典・取得ファイル。原則Git管理外。
- `data/public_it.db` — 公共調達の運用SQLite。
- `src/data/` — Astroビルド時に使う生成データ。
- `public/data/` — ブラウザ・Functionsから参照する公開JSON。
- `dist/` — Astro build成果物。Cloudflareへ配信。

## 6. 画面設計原則
- 日本語を基本言語とする。
- 数字だけでなく「その数字の意味・出典・限界」を近接表示する。
- 億円・兆円・万円等、日本の利用者が読みやすい単位で表示する。
- 負の会計値は赤、それ以外は黒を基本とする。
- モバイルでは横スクロール依存を減らし、必要な表のみ明示的にスクロールさせる。
- データが無い場合は「0」と「未取得」を混同しない。

## 7. SEO基本設計
- canonicalを各index対象ページに付与する。
- `robots.txt` でクロール許可し、sitemapを公開する。
- sitemapは静的ページに加え、index対象の動的企業詳細URLも生成する。
- 上場企業は財務あり企業だけをsitemapへ含める。
- 企業詳細はCorporation / WebPage / BreadcrumbList等の構造化データを出力する。

## 8. キャッシュ・配信ヘッダー
`public/_headers` で共通セキュリティヘッダーを付与する。
公開JSONは `Cache-Control: public, max-age=3600, stale-while-revalidate=86400` とし、更新頻度と配信効率を両立する。
`/vendor/*` は長期immutableキャッシュとする。
動的企業詳細も同様に1時間キャッシュ＋stale-while-revalidateを返す。

## 9. 外部依存の考え方
- データ取得は公式ソースを優先する。
- 外部JSは必要最小限にし、地図等は可能な範囲でサイト内配信する。
- 有料APIがないと成立しない機能は原則採用しない。
- TDnet API等、有料条件があるデータは必須機能にしない。

## 10. 障害分離
- 収集失敗時は公開更新を止める。
- 日次/週次はDB・EDINET索引・正規化を収集前に保存し、未公開失敗時に復元する。ジョブ別の隔離worktreeで公開JSONを生成し、Git正本へ途中変更を残さない。
- トピック収集は日次DBロックから独立する。公開時のみrelease.lockで直列化し、最新mainへ生成差分とソース状態を合流する。
- upload後はrelease-manifestと公開JSON/XMLの内容一致、主要ページのPC/モバイルE2Eを検証する。
- 静的ページと動的Functionsを分離し、Functions障害時も静的領域全体が巻き込まれない構成とする。
- 主要データはpublic向け圧縮JSONとRaw/normalized原本を分離する。

## 11. 変更管理
- GitHub `main` をコードの正本とする。
- UbuntuをRawデータ・運用実行環境の正本とする。
- 生成JSONだけの変更と、ソースコード変更を同一コミットに不用意に混在させない。
- 仕様変更時は本ディレクトリの該当設計書を更新する。

## 12. 話題のトピック配信
`/topics/` は静的ページとし、`collector/collect_wikipedia_topics.py` がWikimedia Analytics APIから直近14日の日別閲覧上位を収集して `public/data/wikipedia-topics.json` を生成する。収集時にMediaWiki/Wikidataでカテゴリ分類し、急上昇上位だけGoogle News RSSの同時期報道を背景候補として補完する。閲覧時の外部API依存は持たない。


## 公共交通データ（2026-10-06追加）

`/transport/` はAstro静的ページと `src/scripts/transport.ts` のEChartsで構成する。3タブ（駅を探す・地域を比較・全国の推移）を設け、初期ロードは駅JSONのみ、地域・全国データはタブを開いた時に取得する。初期表示はJR新宿、地域比較は新宿区と大阪市。17区分の原数値は折りたたみ表、グラフは単独・併用を重複しない8群にまとめる。地理院地図への外部リンクを設ける。公開用JSONは4ファイルで、APIキー不要。ホーム・地域一覧・出典ページから誘導する。


## 共通フッター（2026-10-10）
全静的ページはSiteFooter、動的企業詳細は同じ共通リンク定義とfooter.cssを使用する。トップページと同じ説明・出典／共通リンクの分離、上罫線、折り返しと余白を適用する。ページ固有の出典・免責・戻るリンクは保持し、GitHub・プライバシーポリシーは独立したnavへ置く。無料Web便利ツール集はその下の「関連リンク」に、ロゴ・名称・短い説明・外部リンク矢印付きカードとして配置する。カード全体をリンクとし、スマホでは横幅に合わせる。390px/320pxでは説明とリンクを別行に配置する。


## トピック関連動画の選定（2026-10-10）
Wikipedia急上昇上位10件の関連動画はYouTube Data APIの検索候補からタイトル一致・埋め込み可に加え、取得時点で再生1万回以上のみを選ぶ。YouTube自動生成のTopicチャンネル、自動生成メタデータ、歌詞動画・自動生成を明示するタイトルを除外する。英字1語だけの曖昧なトピックはチャンネル名にも名称が含まれる場合に限る。該当動画がなければカードを出さず、旧選定版のRawキャッシュを再利用しない。再生数はYouTubeの取得時点の値であり動画の品質保証ではない。


## 農業ページの可視化（2026-10-10）
`/agriculture/` は既存領域と同じ紺のヘッダー・青基調のカードUIを使用する。6品目カードに全国の公開額1位を原データから表示し、品目・都道府県・市町村検索で上位10市町村のECharts棒グラフ、1位・金額・公開値の市町村数を同期する。棒または市町村一覧を選択すると、農業全体・選択品目の推計額と、合計を除く公開品目上位8項目の横棒を表示する。横棒は最大品目との比較で構成比ではない。金額は千万円から億円へ換算（÷10）、0は千万円未満と表示。秘匿値は逆算しない。選択市町村はURLへ保持。JavaScript生成要素にもCSSを適用するためページのスタイルをglobalとする。一覧はスクロール領域内の初期15件、次の15件を追加し、スマホの縦長化を抑える。


## 共通ヘッダー（2026-10-11）
全Astroページと企業詳細Functionsはnavigation.jsの同じ定義を使う。「データを探す」「サイト情報」の2項目に集約し、全12領域へ到達できる。「🔥 話題のトピック」は「データを探す」内に入れる。SVGの矢印を中央揃えし開閉で回転させる。ページ固有の一覧・戻る導線は共通ナビ下に保持。ネイティブdetailsでキーボード操作でき、外側クリック・Escapeで閉じ、同時に1つだけ開く。共通ヘッダーは背景#0e1b2e・白文字・内部幅最大1180pxで統一し、ページ固有のH1・導入文もヘッダー内部に置く（不動産、404を含む）。本文の背景は淡色のまま、検索・指標カードは本文領域に残す。navigation.cssでH1をPC最大40px・スマホ28pxに統一し、トップのみPC最大44px・スマホ30pxとする。PC/390px/320pxで全テンプレート・動的詳細のメニュー一致、背景色、見出しの所属、展開・閉じる操作、リンク、重なり・横はみ出し、文字サイズを検証する。


## トップページの見出し・狭幅ナビ（2026-10-11）
トップページのH1「データから、日本を見る。」には絵文字を使わない（データ領域カードの絵文字は維持）。共通メニューはPCと1段に収まるスマホでは従来の左右配置を維持し、狭幅や文字拡大で2段に折り返す場合は2段目の「データを探す」「サイト情報」を左端に揃える。600px以下では自動マージンを除去、380px以下では2段目を明示的に左寄せ。


## 領域タイトル・下層H1・共通ナビ整列（2026-10-11）
領域トップのH1はキャッチコピーではなく領域名を表示する（例：不動産・暮らし、上場企業、未上場企業、国・自治体の案件）。下層ページのH1は既存の意味・名称を維持しつつ、装飾目的の強制改行と末尾の句読点を使わない。共通ヘッダーのDATLUMEロゴと「データを探す」「サイト情報」はページ固有リンク（datlume-context）の有無にかかわらず同一行の中央に縦揃えする。
