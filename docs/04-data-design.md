# DATLUME データ設計書

最終更新: 2026-09-27

## 1. データレイヤ
DATLUMEはデータを3層に分離する。

1. Raw: 取得原本。再検証・再正規化の根拠。
2. Normalized: サイト内共通定義へ整形した中間データ。
3. Public: Web表示に必要な項目だけを圧縮した公開データ。

Rawを直接フロントへ配信しない。PublicからRawへ逆算できるだけの出典識別子を保持する。

## 2. データソース台帳
正式なソース登録は `collector/source_catalog.json` で管理する。
各ソースは最低限以下を持つ。
- label
- enabled
- frequency
- maxAgeHours
- minRecords
- acquisition
- command
- country
- domain

現在は公共調達、地価、地域統計、雇用・賃金、企業・産業、経済・物価、エネルギー等を登録している。

## 3. 公共調達
主要ソースはJETRO政府公共調達、JETRO地方政府、GEPS過去落札実績、自治体公式公開情報。
公共調達の主保存先はSQLiteで、Web向けに年別・集計・企業shard等を生成する。
ソースごとに日付・金額・税区分・収録対象が異なるため、完全な同一母集団として扱わない。

## 4. 上場企業マスタ
JPX「東証上場銘柄一覧」と金融庁EDINETコードリストを突合する。
証券コードは普通株の4文字コードを主キーとして扱う。
市場、33業種、17業種、EDINETコード、法人番号等を可能な範囲で保持する。
5桁末尾0のコードは普通株4文字へ正規化する。

## 5. EDINET財務
主ソースはEDINET API v2の有価証券報告書XBRL/変換CSV。
会計値は以下の属性を意識して選択する。
- 連結/個別
- 対象期間
- instant/duration context
- unit
- 会計基準
- 訂正報告書
- EDINET document ID

原則として連結財務を優先し、連結財務が存在しない企業だけ個別財務を採用する。
タグ名の文字列一致だけで売上・利益・資産等を決定してはならない。

## 6. 金融業
銀行・保険・証券等は一般企業と収益・負債構造が異なる。
銀行は経常収益・経常利益、保険は保険収益・税引前利益等を優先表示する。
営業利益率や一般企業型の負債評価を機械的に適用しない。
ランキングも不適切な共通指標から金融業を除外する。

## 7. 平均年間給与
EDINET変換CSVのfactだけを無条件に信用しない。
外れ値候補は元iXBRLの表示値と表単位を照合する。
現在の異常検知基準は100万円未満、2,000万円超、企業内・前年比3倍以上の変動。
原典で検証できない候補が残った場合は処理を失敗させ、本番公開を止める。

## 8. 欠損値
- `null`/未取得と数値0を区別する。
- 「該当なし」「金額未確認」「データ未取得」を意味に応じて区別する。
- 欠損を平均値、推計値、前年度値で勝手に埋めない。
- 企業固有の年齢別給与分布等、一次データが無いものは生成しない。

## 9. 上場企業Publicデータ
`public/data/listed-companies/` に以下を生成する。
- `master.json` — 企業マスタ
- `index.json` — 検索・一覧向け最新指標
- `rankings.json` — 指標別ランキング
- `summary.json` — 件数・生成日時等
- `details/{00..3f}.json` — 64分割の企業詳細shard

詳細shardはコードから決定的にbucketを計算するため、Function側で検索インデックスやDBを持たずに1ファイルで対象企業へ到達できる。

## 10. 公開調達企業Publicデータ
公共調達の企業詳細は256 shardで保持する。
企業IDの一部をbucketとして利用し、Pages Functionが `/data/company-details/{00..ff}.json` から対象企業を取得する。

## 11. 派生値
派生値は式が明示できるものに限定する。
例:
- 推計年収 = 月額現金給与×12 + 年間賞与等
- 売上成長率 = (当期 - 前期) / |前期| × 100
- free cash flow等、元値から定義可能なもの
派生値は元統計そのものと誤認しないよう「参考値」「DATLUME算出」等を明示する。

## 12. データ保持
- EDINET年次報告Rawは長期保持対象とし、自動削除しない。
- その他Rawは運用スクリプトで古い一時取得物を整理できる。
- 公共調達DBバックアップは日次で作成し、7日超を整理する。
- 公開JSONは再生成可能な成果物として扱う。
