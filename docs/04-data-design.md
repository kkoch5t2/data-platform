# DATLUME データ設計書

最終更新: 2026-10-05

## 1. データレイヤ
DATLUMEはデータを3層に分離する。

1. Raw: 取得原本。再検証・再正規化の根拠。
2. Normalized: サイト内共通定義へ整形した中間データ。
3. Public: Web表示に必要な項目だけを圧縮した公開データ。

Rawを直接フロントへ配信しない。PublicからRawへ逆算できるだけの出典識別子を保持する。

## 2. データソース台帳
正式なソース登録は `collector/source_catalog.json` で管理する。
各ソースは最低限以下を持つ。
- label
- enabled
- frequency
- maxAgeHours
- minRecords
- acquisition
- command
- country
- domain

現在は公共調達、地価、地域統計、雇用・賃金、企業・産業、経済・物価、エネルギー等を登録している。

## 3. 公共調達
主要ソースはJETRO政府公共調達、JETRO地方政府、GEPS過去落札実績、自治体公式公開情報。
公共調達の主保存先はSQLiteで、Web向けに年別・集計・企業shard等を生成する。
ソースごとに日付・金額・税区分・収録対象が異なるため、完全な同一母集団として扱わない。
- noticeDate は公告・公示日、awardDate は落札決定日。福岡市の bidDate（入札日）と contractDate（契約日）は別フィールドに保存し、eventDate は一覧と年別配置のための表示用日付とする。processStatus は中止・不調・取止め等を明示する。
- 福岡市の原典で暦上不正な契約日は公開値を null とし、Raw値・理由・発見日時を source_quality_issues に保存する。
- 札幌市の同一契約の再公表は契約属性から計算した contract_key で統合し、個々の掲載日・元行IDを procurement_publications に残す。掲載日は最初の日を維持する。
- GEPSのDBが存在する場合、JETROのJSON復元からGEPS行を読み戻さない。公式スナップショットで削除・訂正された旧行が前回公開JSONから復活することを防ぐ。GEPS行がないDBの初期復元ではJSONを利用できるが、その後はGEPS公式取得・監査を通す。
- JETROの公示をGEPSの最終収録日だけで一括除外しない。両ソースのレコードを保持するが、同一契約の完全な名寄せは未実施。件数・合計金額は掲載行の集計であり、ユニーク契約数・総額とは解釈しない。
- 受注企業名は公開データ生成時に保存済みレコードもNFKC、法人略記、空白の既定ルールで正規化し、企業IDでは英字大小文字の差を同一視する。同じ社名ベース企業IDでは表示名を1つにそろえる。これは法人番号で一意化した法的な企業IDではない。同一正規化名が国税庁法人マスタの複数法人に一致する場合は別法人を推測で統合・断定せず、社名ベース集計として明示する。元レコードの出典IDと金額は変更しない。
- 未上場公開対象は国税庁の現存法人のうち、JPXマスタの法人番号およびEDINET上場法人番号に一致しない会社に限る。JPX上場銘柄に法人番号がない場合、法人名の正規化一致候補は同一法人と断定せず、未上場一覧から保留して公開しない。上場企業の子会社・過去に上場していた企業は、当該法人自身が上場していなければ対象に含む。JPXマスタの基準日以降の新規上場は次回マスタ更新まで反映されない。
- 未上場企業の法人基本情報は国税庁法人番号マスタに基づく。社名を用いた一意候補の発見は法人の実在とページ候補の選定にだけ使用し、調達レコードの法人帰属・受注実績の証拠とはしない。
- 法人別調達実績は、同じ公式案件の受注者欄に法人番号が掲載され、出典ID・社名・番号が国税庁の法人名と一致するレコードだけを計上する。支店・営業所名は明示された支店表記に限り認め、共同企業体の代表企業番号は共同企業体の受注額へ転嫁しない。番号、出典URL、収集時に整形した詳細文、抽出方法、照合状態を案件単位で保持する。
- 法人ページの案件表は出典IDで絞る。社名別企業ID全体の案件を法人ページへ展開しない。社名別の調達ページと元案件の件数・金額は維持し、未確認の法人帰属は未確認として扱う。
- 未上場企業トップの受注額ランキングは1種類に絞る。`name-groups.json` は国税庁の現存未上場法人と社名が一意に一致する受注者表記のうち、金額のある社名別集計上位12件を保持し、調達の社名別ページへリンクする。法人番号はこのランキングに持たせず、同名候補から案件の法人帰属を推論しない。企業検索では法人確認案件がない会社に0件の調達実績を表示しない。法人詳細の調達実績は原典で番号を確認できた案件だけとし、ない場合は空状態を示す。社名別上位に同じ名前があるときは、法人への帰属を示さないリンクとして社名別案件ページへ案内する。
- 契約方式図とそのフィルターは、各原典の細かな方式表記を一般競争入札・指名競争入札・随意契約・見積・見積合わせ等の大分類へ写像する。一般/一般競争入札、随意/随契/随意契約は同じ分類にする。条件付・WTO・定例見積等の原表記はSQLiteと年別出典レコードに残す。単価契約・中止・不調など方式ではない値は図から除く。
- 落札・選定基準図は明記された最低価格・総合評価・最高価格・価格競争だけを数える。自治体のaward_method欄へ契約方式が複写された場合は基準として数えず、欠損のままにする。両図は別の意味・異なる有効件数の部分集合であり、合計が収録総件数に一致するとは限らない。

## 4. 上場企業マスタ
JPX「東証上場銘柄一覧」と金融庁EDINETコードリストを突合する。
証券コードは普通株の4文字コードを主キーとして扱う。
市場、33業種、17業種、EDINETコード、法人番号等を可能な範囲で保持する。
5桁末尾0のコードは普通株4文字へ正規化する。

## 5. EDINET財務
主ソースはEDINET API v2の有価証券報告書XBRL/変換CSV。
会計値は以下の属性を意識して選択する。
- 連結/個別
- 対象期間
- instant/duration context
- unit ID / 表示単位
- 会計基準
- 訂正報告書
- EDINET document ID

企業財務には企業内容等開示府令の年次報告（`ordinanceCode=010`）だけを採用し、同じEDINETコードに紐づくファンド等の年次文書を混在させない。
原則として連結財務を優先し、連結財務が存在しない企業だけ個別財務を採用する。
概念は完全一致の許可リスト（および明示した完全一致ラベルfallback）で選び、タグ名の部分一致・推測一致は使用しない。同一contextに複数の利益概念がある場合は、連結企業の純利益では「親会社株主/所有者に帰属する利益」を総利益より優先する。
公開画面の企業間比較は円建てを前提とするため、金額指標はEDINETの `unit ID=JPY`（または明示単位「円」）だけを採用する。USD等の外貨factを円として扱わず、同一文書に円換算factが無い指標は欠損のままにする。
従業員数・発行済株式数は通貨unitを拒否し、取得済みiXBRLがある場合は表示表の「人/名」「株/千株」と照合してpresentation単位も検証する。

EDINET原典自体の明確な桁・表示不整合は、文書ID・指標・根拠を `source_corrections.py` に明示した検証済み補正だけ許可する。前年比だけを根拠に自動補正せず、新しい異常候補は監査失敗として公開を止めて原典確認する。訂正値を原典から一意に確定できない場合は推測補完せず `null` とし、原典異常をそのまま利用者向け数値として公開しない。

## 6. 金融業
銀行・保険・証券等は一般企業と収益・負債構造が異なる。
銀行は経常収益・経常利益、保険は保険収益・税引前利益等を優先表示する。
営業利益率や一般企業型の負債評価を機械的に適用しない。
ランキングも不適切な共通指標から金融業を除外する。

## 7. 平均年間給与
EDINET変換CSVのfactだけを無条件に信用しない。
外れ値候補は元iXBRLの表示値と表単位を照合する。
現在の異常検知基準は100万円未満、2,000万円超、企業内・前年比3倍以上の変動。
原典で検証できない候補が残った場合は処理を失敗させ、本番公開を止める。

## 8. 欠損値
- `null`/未取得と数値0を区別する。
- 「該当なし」「金額未確認」「データ未取得」を意味に応じて区別する。
- 欠損を平均値、推計値、前年度値で勝手に埋めない。
- 企業固有の年齢別給与分布等、一次データが無いものは生成しない。
- 公式表そのものに対象がない欠損は「収集漏れ」と区別して保持する。例として2025年家計調査の年間表では大津市が収録されず、滋賀県の年間光熱・水道値はsource-nativeな欠損として扱う。

## 9. 上場企業Publicデータ
`public/data/listed-companies/` に以下を生成する。
- `master.json` — 企業マスタ
- `index.json` — 検索・一覧向け最新指標
- `rankings.json` — 指標別ランキング
- `summary.json` — 件数・生成日時等
- `details/{00..3f}.json` — 64分割の企業詳細shard

詳細shardはコードから決定的にbucketを計算するため、Function側で検索インデックスやDBを持たずに1ファイルで対象企業へ到達できる。

## 10. 公開調達企業Publicデータ
公共調達の企業詳細は256 shardで保持する。
企業IDの一部をbucketとして利用し、Pages Functionが `/data/company-details/{00..ff}.json` から対象企業を取得する。

## 11. 派生値
派生値は式が明示できるものに限定する。
例:
- 推計年収 = 月額現金給与×12 + 年間賞与等
- 売上成長率 = (当期 - 前期) / |前期| × 100
- free cash flow等、元値から定義可能なもの
派生値は元統計そのものと誤認しないよう「参考値」「DATLUME算出」等を明示する。

## 12. データ保持
- EDINET年次報告Rawは長期保持対象とし、自動削除しない。
- 公共調達を含むRawの出典原本は自動一括削除しない。再取得可能性と照合した個別の保存期限を別途定義する。
- 公共調達DBバックアップは日次で作成し、7日超を整理する。
- 公開JSONは再生成可能な成果物として扱う。

## 13. ライセンス・出典
各データの権利・利用条件は提供元に帰属する。
リポジトリのMIT Licenseは収集済み第三者データへ自動適用しない。
画面上および `/about-data/` で出典・範囲・注意点を明示する。

## 14. Wikipedia話題トピック
- 主ソース: Wikimedia Analytics API / Japanese Wikipedia Pageviews。補助メタデータ: MediaWiki Action API / Wikidata。ニュース背景候補: Google News RSS（日本向け検索）。
- 粒度: 日別・記事別。access=`all-access`。
- Raw: APIレスポンスを日別JSONで保持。
- Public: 最新TOP100、前日比、7日ベースライン、急上昇、週間合計、14日日別集計。
- 特殊ページやWikipedia内部運用ページは除外する。
- 欠損日は0で補完せず、取得できた最新日を基準にする。
- `schemaVersion=2` では各TOP100に `category`（key/label/emoji/confidence/evidence）と `trend`（new/spike/rising/gradual/evergreen/steady）を付与する。急上昇上位の `reason` は同時期ニュースの件数・見出し・媒体・URLを保持するが、原因推定ではなく時期一致の背景候補である。
- 「日本語版Wikipediaでの閲覧関心」であり、日本居住者だけの行動、日本全体の検索量、ニュース重要度、世論とはみなさない。


## しょくばらぼ職場情報（2026-10-05追加）
ソース：厚労省しょくばらぼ公式全件CSV（CP932、日次配布）。Raw ZIP・SHA-256・ファイル名の日付を保持。法人番号重複/スキーマ変更/10%以上の収録減で停止。所定外労働と法定時間外/休日労働、全体と区分別有給率は別metric。原典display・unit・scope・note・企業更新日時を保持。100%を超える有給取得率は繰越等があり原典どおり扱う。採用は原典の3年度区分を保持し暦年や定着率を推計しない。取得情報がない企業はworkplace=null。職場情報のある会社を社名で他法人へ割り当てない。商用利用可能な公式利用ルールに従い、出典と加工表記を付す。

## 15. 社人研・市区町村将来人口（2026-10-05追加）
- 原典：社人研「日本の地域別将来推計人口（令和5（2023）年推計）」結果表1、2-1～2-3（XLSX）。Raw原本とSHA-256を保存し、2020年を国勢調査基準人口、2025～2050年を5年刻みの将来推計として保持する。実績時系列に混ぜない。
- 4表の自治体コード・区分・名称を照合し、総人口、0～14歳、15～64歳、65歳以上を収録。2020年の年齢不詳は3区分に含まれず、将来年は3区分合計が総人口に一致する。
- 47都道府県、1,884推計地域、政令指定都市20市の区合計行を保持する。区合計は地域数に加えない。福島県浜通り13市町村の個別推計は存在しないため、合算の浜通り地域（07999）のみを公開する。
- 地図の点はSSDSE-Aの自治体代表点とコード・名称が一致する1,728件（政令指定都市合計を含む）に限定し、区等の未照合座標を推測しない。2020年の総人口はSSDSE-Aの同一コードと照合する。行政区画は2023年12月の原典区分であり、現行境界の値とは限らない。


### 小売物価統計（動向編）の長期系列

e-Stat「主要品目の都市別小売価格」の2000年1月～2024年8月を月別XLS/XLSXから取り込み、現行の直近24か月と接続する。原表と月別のパース済みスナップショットは data/raw/retail-prices-city-history と data/normalized/retail-prices-city-history に保持（公開対象外）。公開JSON public/data/retail-prices-city-monthly.json は13品目・90都市系列・月連続の schemaVersion 2。古い都市の名称を現行市へ無断で付け替えない。米の10kg原値は5kg換算、unitConversions に対象月を記録する。単位の互換が確認できない値は null とし、incompatibleHistoricalUnits に原単位を記録する。最新月の都市ランキングだけを計算し、過去の欠損は補完しない。

## Gビズインフォの補助金・特許情報（2026-10-05追加）
- 公式配布の補助金情報・特許情報ZIPを月次で保存する。法人番号がJPX/EDINETまたは国税庁法人マスタで確認された企業詳細だけへ照合し、社名一致による帰属は行わない。
- 補助金は証明日・名称・発行元・記載金額を原典どおり表示する。空欄は欠損、マイナス値は原値であり、金額を一律に足して交付総額とは呼ばない。全項目が同一の重複行は1記録にまとめ、最新8件を表示する。
- 特許は「特許」の行だけを採用し、意匠・商標は混在させない。法人番号＋登録番号でFI分類等の重複行を1件にし、件数と出願日順の最新8件を表示する。出願日は登録日や権利の現存状態ではない。登録番号がない行は件数に入れない。
- ZIP名の配布日と個別記録の日付は区別する。最新スナップショットが欠けた場合は公開データを無言で空にせず生成を停止する。
