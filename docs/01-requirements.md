# DATLUME 要件定義書

最終更新: 2026-09-27

## 1. 目的
DATLUME は、日本の公共・公的データをテーマ別に収集・整理・可視化し、一般利用者が専門的な元資料を直接読み込まなくても比較・把握できる状態を作るデータサイトである。
対象は単一分野に限定せず、共通の収集・監査・公開基盤上で領域を拡張する。

## 2. 公開URLとリポジトリ
- 本番: `https://datlume.com/`
- GitHub: `kkoch5t2/data-platform`
- Ubuntu 正本: `/home/kota/Sites/public-market-data`
- 配信: Cloudflare Pages + Pages Functions

## 3. 対象ユーザー
- 日本の統計・企業・地域情報を直感的に確認したい一般利用者
- 企業比較、転職・年収調査、地域比較、公共調達調査を行う利用者
- 元統計の定義や収録範囲まで確認したい実務利用者

## 4. 現在の公開領域
1. 国・自治体の案件（公共調達）
2. 不動産・暮らし
3. 都道府県別推移
4. 雇用・賃金
5. 企業・産業
6. 上場企業
7. 経済・物価
8. エネルギー

## 5. 基本方針
- 公式API、公式CSV/XLSX/JSON、公式Web公開情報を優先する。
- 有料API・有料SaaSを必須依存にしない。
- 欠損値、企業固有値、関係性を推測で補完しない。
- Rawデータを保持し、公開用データは別途正規化・集約する。
- 更新はリアルタイムではなくバッチ処理とする。
- 静的配信を基本とし、必要な詳細ページのみFunctionsで動的生成する。

## 6. 機能要件
### 6.1 共通
- テーマ別トップ、詳細、ランキング、比較、グラフ、地図等を提供する。
- canonical、sitemap、robots、meta description等のSEO基盤を持つ。
- データ出典、集計方法、注意点を `/about-data/` で明示する。
- プライバシー・広告・Cookieの説明を `/privacy/` で明示する。
- PCとスマートフォンで主要操作が成立するレスポンシブUIとする。

### 6.2 公共調達
- JETRO、GEPS、自治体公式データを統合する。
- 分野、年度、発注機関、受注企業、技術タグ等から閲覧できる。
- 金額確認済み案件のみを金額集計へ含める。
- 収録総額を市場全体の完全な市場規模として表現しない。

### 6.3 上場企業
- JPX上場銘柄一覧とEDINETを突合した企業マスタを提供する。
- 業績、BS、CF、従業員、平均年間給与、セグメント、主要株主を確認できる範囲で表示する。
- 2〜5社比較、業種比較、ランキング、10年推移を提供する。
- 財務データがない企業はページを残しても `noindex,follow` とし、sitemapから除外する。
- 銀行・保険等は一般企業と同じ財務意味で評価しない。

## 7. 非機能要件
- 追加固定費を極小化し、原則Cloudflare無料枠・公開データで運用する。
- 本番デプロイ前にファイル数20,000以下、単一ファイル25MiB以下を検査する。
- 生成データの異常、リンク切れ、JSエラー、表示崩れを自動監査する。
- 収集失敗時に壊れたデータをそのまま本番公開しない。
- EDINET等のシークレットをGit・ログ・public配下へ出さない。
- 日次処理は同時実行をロックし、成功済み日は重複実行を避ける。

## 8. データ品質要件
- 原典の単位・期間・会計基準・context・document IDを保持して解釈する。
- EDINETは連結財務を優先し、連結が存在しない場合のみ個別財務を使う。
- タグ名の部分一致だけで財務項目を決定しない。
- 平均年間給与は表示値・単位不整合を検知し、異常候補を原典iXBRLで再検証する。
- 上場企業の主要株主リンクは一意に企業照合できる場合だけ付与する。
- セグメントは正式名称と値を確認できる場合だけ表示する。

## 9. 収益化要件
- Google AdSenseを主要な初期収益化手段とする。
- `ads.txt`、所有権確認、プライバシーポリシー、CMP対応を維持する。
- 審査完了前は広告配信スクリプトを無理に有効化しない。
- 審査通過後もUXを損なう広告密度にしない。
- データ未取得・薄いページへ機械的に広告を増やさない。

## 10. 完了条件
機能追加・データ更新を「完了」とするには、原則として以下を満たす。
- 元データ取得または仕様変更が正しく反映されている。
- `npm run audit:data` が成功する。
- `npm run build` と `npm run audit:html` が成功する。
- 対象ページのPC/390px E2Eが成功する。
- 必要な場合はGit commit/pushとCloudflare本番反映を行う。
- 本番URLで表示・HTTP・主要操作を再確認する。
